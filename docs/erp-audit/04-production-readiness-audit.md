# 04 — Production readiness and finding register

**Release decision (R): not ready for a real-data, broadly accessible pilot.** The application compiles and starts with placeholders. That is a useful foundation, but does not establish secure access, repeatable schema setup, durable recovery or working business integrations. Preserve the implementation and close the gates below.

Scope/evidence labels are defined in [README](README.md). Priorities are deployment decisions, not CVSS scores. **P0 blocker** gates the affected exposure or workflow; a conditional feature may remain server-side disabled in a restricted pilot. **P1 before broad user rollout** must close before general use of the affected module. **P2 hardening** follows verified pilot operation. “Unknown” means not provided/tested, not proven absent outside the ZIP.

## Dependency assessment detail

F: production audit package entries are `next`, `sharp`, `postcss`, `nanoid`, `uuid`, `exceljs`; this is **not** six independently demonstrated application exploits. The direct root PostCSS version does not eliminate a vulnerable nested dependency. All results are time-sensitive as of 2026-09-23.

Primary advisories: [Next.js Windows-hosted RCE](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36) and [AVIF image optimization RCE](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) identify 15.5.24 as the patched 15.x release. Windows filesystem prerequisites are outside the proposed Linux target. AVIF optimization exposure depends on actual image inputs/configuration and was not exercised. R: update to a reviewed compatible patched release and transitive tree rather than relying solely on a reachability assumption. Additional advisory URLs and ranges remain in [dependency-audit.json](evidence/dependency-audit.json).

## Release gates (R)

**G0 — audit reviewed:** independent deliverables and baseline reconciliation complete; separate ChatGPT reviewer disposition and business decisions recorded as in [08](08-prioritized-implementation-plan.md). Still pending second-reviewer sign-off.

**G1 — private technical staging:** F01/F02/F19/F20 resolved; CI image boots with isolated DB/buckets and synthetic fixtures. Secrets validated. No real PII, live Sheets writes or external recipients. Branch protection/review and rollback procedure exist.

**G2 — invited production-like pilot:** F03/F04/F18 complete; applicable F05/F07/F09 closed **or enforced server-side disabled**, public exposure limited, health/restore verified. Core test journeys succeed with allowed pilot data. Feedback path usable by each pilot role. Selected module P1 issues must be fixed before that module handles consequential real records; notably invoices, salary/approvals and Sheets cut-over.

**G3 — broader use / source cut-over:** remaining applicable P1 controls closed, BA/domain-owner acceptance and reconciliation signed, operator support/recovery rehearsed, monitoring and cost measured. Intelligence remains adapter-only; its action privileges stay disabled until F22 contract gates pass.

No gate is marked accepted by this audit merely because its design has been written.
